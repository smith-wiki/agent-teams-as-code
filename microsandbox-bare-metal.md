# Bare-metal Linux: run one named APM agent in a local microVM

Microsandbox’s local CLI/SDK starts the sandbox process directly, with **no daemon or remote service**. A Linux host needs glibc 2.28+ and readable/writable `/dev/kvm`; nested VM/container hosts must expose hardware virtualization ([local backend](https://docs.microsandbox.dev/getting-started/introduction), [Linux requirements](https://docs.microsandbox.dev/troubleshooting/linux)). The beta project may break compatibility; pin a release ([official repository](https://github.com/superradcompany/microsandbox#requirements)).

## One-agent delivery path

1. Build and digest-pin an OCI runtime image containing **OpenCode**, APM CLI and OS dependencies. Microsandbox accepts standard OCI images from Docker Hub, GHCR and other OCI registries; the base is read-only and each sandbox gets a private writable layer ([images](https://docs.microsandbox.dev/images/overview), [filesystem boundary](https://docs.microsandbox.dev/security/filesystem)). The repository’s `.apm/` package is source/configuration, **not** that runtime image.
2. Produce a reviewed repository artifact containing `apm.yml`, `apm.lock.yaml`, `.apm/` and source, but no `.env`, Git credentials or remotes. Copy it into the guest at `/workspace` with `--copy-dir` or `msb copy`; unlike a bind mount, this does not expose a live host path ([CLI copy](https://docs.microsandbox.dev/cli/sandbox-commands#msb-copy), [OpenCode isolated-copy example](https://docs.microsandbox.dev/examples/agents/opencode)).
3. Inside the guest, run `apm install --target opencode --frozen` from `/workspace` unless CI already materialized the artifact. APM places `.apm/agents/reviewer.agent.md` at `.opencode/agents/reviewer.md`; the selected harness can then run that **named** profile, for example `msb exec reviewer -- sh -lc 'cd /workspace && opencode run --agent reviewer "Review the supplied change"'`. This assumes a named `reviewer` sandbox already created from the runtime image and supplied the copied artifact. The agent name is passed to OpenCode, not to microsandbox; other harnesses need their own supported named-agent launch path ([APM target matrix](https://microsoft.github.io/apm/reference/targets-matrix/#opencode), [OpenCode run CLI](https://opencode.ai/docs/cli/#run-1), [agent modes](https://opencode.ai/docs/agents/#mode), [microsandbox OpenCode example](https://docs.microsandbox.dev/examples/agents/opencode)). There is no Microsandbox or APM `AgentTeam` runtime object.

Do not mount `$HOME`, SSH/agent sockets or the whole checkout. Prefer copied least-privilege input and export a patch/result explicitly. Use a host-environment secret reference, not a raw SDK value (persisted in host config after stop); destination-bound substitution gives the guest only a placeholder, but an allowed endpoint can still echo it. Verify that the chosen harness actually sends that placeholder through inspectable HTTPS to the bound host before relying on this credential path ([secret boundary](https://docs.microsandbox.dev/security/secrets), [substitution limits](https://docs.microsandbox.dev/sandboxes/secrets)).

## Wake and sleep

A durable host supervisor must own the event listener, queue/cursor and lease outside the VM. An attached local SDK sandbox stops when its application exits; detach it to outlive the caller. `pause` freezes processes in resident RAM; `resume` continues them. `stop` powers the VM off but keeps disk/configuration; `start` boots fresh and does **not** resume processes ([lifecycle](https://docs.microsandbox.dev/sandboxes/lifecycle)). A disk snapshot saves files and boots fresh; a full snapshot saves RAM/processes and resumes them, but host connections must reconnect and restore requires compatible runtime/guest kernel plus matching CPU/memory. `.msb` archives can move snapshots between machines, yet those full-state constraints—and Unix/Windows owned-directory restrictions—mean they are not universally portable ([snapshots](https://docs.microsandbox.dev/sandboxes/snapshots#snapshot-types), [snapshot archives](https://docs.microsandbox.dev/sandboxes/snapshots#export-and-restore)).
