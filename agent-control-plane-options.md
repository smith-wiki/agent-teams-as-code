# The operator layer must compose runtime, identity and provider adapters

**Finding:** no reviewed product documents a turnkey **APM → Microsandbox → Kubernetes or bare-metal → provider accounts** path. APM projects agent files into supported harnesses; its separate `apm runtime` command installs selected AI CLIs, not a running worker ([APM install](https://microsoft.github.io/apm/reference/cli/install/), [APM runtime](https://microsoft.github.io/apm/reference/cli/runtime/)). The current Microsandbox local CLI/SDK boots microVMs, but is not a documented APM or Kubernetes controller ([current project](https://github.com/superradcompany/microsandbox)).

| Option | Verified boundary |
|---|---|
| **kagent** | The closest integrated Kubernetes path **if the runtime may change**: `AgentHarness` (v0.9.9+) provisions OpenClaw or Hermes on **Agent Substrate**, not Microsandbox ([concept](https://kagent.dev/docs/kagent/0.x/concepts/agent-harness/)). Its Slack integration consumes pre-created bot/app token `Secret` references and does not create the Slack app or account ([example](https://kagent.dev/docs/kagent/0.x/examples/agent-harness/)). |
| **Rossoctl (formerly Kagenti)** | Enrols existing Deployments through `AgentRuntime` and injects SPIFFE/Keycloak auth. SPIFFE is workload identity, not a Slack/Zulip/mailbox or model-provider account. OAuth client credentials are created out of band and supplied as a Secret ([project rename](https://github.com/kagenti/kagenti#readme), [operator](https://github.com/rossoctl/operator#readme)). |
| **SIG Apps Agent Sandbox** | Its `Sandbox` CRD manages stateful Pods, storage and pause/resume; isolation comes from runtimes such as gVisor or Kata. Its stable hostname/network identity is not credential identity, Microsandbox, or account provisioning ([scope](https://github.com/kubernetes-sigs/agent-sandbox#readme)). |
| **Crossplane + External Secrets Operator (ESO)** | Crossplane creates only resources implemented by an installed provider; unsupported SaaS needs a provider/custom controller ([contract](https://docs.crossplane.io/latest/packages/providers/)). ESO syncs values and has enumerated token generators, but not secret/account lifecycle; for example, GitHub requires a pre-registered App and GitLab an admin API token ([generators](https://external-secrets.io/latest/guides/generator/)). |

Account creation is **provider-specific, not just secret synchronization**. Slack offers [`apps.manifest.create`](https://docs.slack.dev/app-manifests/configuring-apps-with-app-manifests/#manifest_apis) after an authorized operator obtains an app-configuration token; Zulip’s documented [bot-creation flow](https://zulip.com/help/add-a-bot-or-integration) is in its UI, so do not promise unattended bot creation there without another supported interface. Google Workspace [creates users through the Directory API](https://developers.google.com/workspace/admin/directory/v1/guides/manage-users), but a Gmail mailbox also needs licensing and setup ([identity boundary](identity-reconciliation.md)). Initial tenant-admin authority, billing and provider approvals cannot be conjured from an agent manifest.

## Recommended second layer

For **Microsandbox on Kubernetes**, a project-specific reconciler must map each repository agent to a guest image and supported harness invocation, provision external identities through available provider admin APIs (or explicit human gates), then schedule a KVM-capable host worker as described in the [Kubernetes deployment path](microsandbox-kubernetes.md). Persist each provider’s immutable remote ID and secret *reference*, never the secret value, in the desired-state record. Keep bootstrap credentials in Vault/cloud secret manager; ESO can deliver already-created values to the trusted host worker, which supplies only that agent’s host-environment references to Microsandbox. Use distinct workload principals and least-privilege provider roles; ESO recommends scoped RBAC and narrow stores ([ESO guidance](https://external-secrets.io/latest/guides/security-best-practices/), [Microsandbox secret boundary](https://docs.microsandbox.dev/security/secrets)). If gVisor instead of Microsandbox is acceptable, kagent `AgentHarness` handles agent runtime lifecycle but still needs a translation from APM content and provider-specific account provisioning ([harness backends](https://kagent.dev/docs/kagent/0.x/concepts/agent-harness/)).

On bare metal, use Nomad/systemd plus a custom Microsandbox CLI/SDK adapter and Vault; Nomad mints task-scoped Vault tokens and renews them ([integration](https://developer.hashicorp.com/nomad/docs/secure/vault)). Microsandbox host-side substitution can keep values outside guests, but raw SDK values persist in host configuration; prefer host-environment references and narrow allowed hosts ([boundary](https://docs.microsandbox.dev/security/secrets)). External account creation remains the same custom privileged reconciler.
